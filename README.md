# TwitchCut v0.2

Находит лучшие моменты стрима Twitch (в записи или прямо во время эфира) и монтирует из них вертикальные клипы 9:16 для TikTok, Shorts и Reels. Моменты ищутся по смыслу речи, а не только по чату. Есть автоматическая раскладка кадра, анимированные субтитры, незаметное заглушение мата и варианты названий для TikTok.

## Установка (Windows)

1. Запустите `setup.bat`. Он сам поставит Python 3.12 (если его нет), библиотеки, FFmpeg и **Claude Code**, а затем откроет браузер для входа в Claude: войдите аккаунтом с подпиской Pro или Max. Займёт 5–15 минут.
2. Запустите `start.bat`: откроется TwitchCut в браузере. Вкладка «Статус» покажет, всё ли готово.

Если вход в Claude не удался или вы сменили аккаунт, запустите `login_claude.bat`.

3. *(Рекомендуется)* Запустите `setup_gpu.bat`: речь будет распознаваться **видеокартой** (AMD, Intel или NVIDIA, в том числе встроенной) **одновременно с процессором**. Подробнее — в разделе «Распознавание речи на видеокарте».

Монтаж тоже ускоряется видеокартой AMD, NVIDIA или Intel, если она есть.

## Как пользоваться

1. **Стримеры:** добавьте канал и опишите стримера: характер, мемы, коронные фразы, что любит чат, эмоуты канала. Это описание Claude получает при каждом анализе, оно сильнее всего влияет на то, какие моменты он посчитает смешными.
2. **Новая нарезка:** выберите стримера, и появятся его последние записи. Нажмите на запись (или вставьте ссылку), выберите режим анализа и нажмите «Нарезать».
3. Готовые клипы появятся на странице задачи. Их можно посмотреть, скачать и скопировать описание с хештегами. Файлы лежат в `workspace\vod_<id>\clips\`.

Командная строка тоже работает: `cut.bat https://www.twitch.tv/videos/123456789 --clips 5`

## Как это работает

```
VOD ─► чат + звук + клипы зрителей ─► всплески реакций (быстро, по всему стриму)
    ─► распознавание ВСЕЙ речи (Whisper: видеокарта + процессор, по 10 минут с сохранением)
    ─► Claude читает весь стрим кусками по 25 минут: истории, новости, мнения,
       интересное, драма — даже если чат молчал
    ─► объединение: «по смыслу» + «по реакции» → до 40 кандидатов
    ─► Claude оценивает каждого как продюсер TikTok: хук, понятность без контекста,
       ценность, актуальность, комментируемость; выбирает границы, отмечает «воду»
       внутри (донат не по теме, повторы, поиск), пишет 2 варианта названия и теги
    ─► скачиваются только нужные куски видео в лучшем качестве (1440p, если есть)
    ─► монтаж 9:16: раскладка, субтитры по словам, заглушение мата, громкость -14 LUFS
```

**Глубина анализа.** «Глубокий» режим (по умолчанию) распознаёт весь стрим, и Claude ищет моменты по смыслу. На процессоре это примерно 10–25 минут на час стрима; распознанное сохраняется, поэтому после перезапуска работа продолжается. «Быстрый» режим анализирует только места, где оживился чат: быстро, но «тихие» истории и новости пропускаются.

**Оценка моментов.** Главное — смысл сказанного. Чат и громкость служат подсказками. Громкий крик без понятного повода оценивается низко, а новость или история при тихом чате — высоко, если она интересна широкой аудитории. Промпты лежат в `twitchcut/llm.py` (оценка) и `twitchcut/scan.py` (поиск), их стоит дорабатывать по результатам.

**Названия.** На видео ничего не пишется. Для каждого клипа предлагается 2 варианта названия для TikTok (суть и интрига) и 3–5 хештегов. Нажатие копирует. Всё это также сохраняется в `.txt` рядом с клипом.

**Где вебка**, определяется сразу по **всем** клипам стрима: вебка весь стрим стоит на одном месте, а лица из роликов, которые смотрит стример, в разных клипах разные. Так TwitchCut не путает стримера с человеком из видео на экране. Границы самой картинки вебки находятся по её рамке, поэтому в зону вебки не попадают чат и куски экрана. Найденное положение запоминается для стримера и помогает в следующих нарезках и в эфире. Если всё же ошибся — в карточке стримера нажмите **«Указать»** и обведите вебку мышкой на кадре из стрима.

**Раскладка кадра** выбирается автоматически **для каждого куска клипа**, и лицо стримера при этом видно всегда:
- пока на экране что-то идёт (видео, игра) и стример это комментирует — **вебка сверху, экран снизу**; экран кадрируется по тому месту, где идёт действие;
- если экран стоит (видео на паузе, OBS, статичная страница), а стример долго рассказывает (от 7 с) — **только вебка**; когда на экране снова что-то происходит — обратно;
- первые ~8 секунд клипа показывается экран, чтобы было понятно, о чём речь; если экран стоит весь клип — весь клип только вебка;
- лица людей из роликов на экране никогда не занимают кадр вместо стримера;
- зона вебки подгоняется под пропорции самой вебки, поэтому она входит **целиком**, без обрезанных краёв.
Рамка вебки ищется по прямым линиям, которые есть почти в каждом кадре, с учётом типичных пропорций камеры (16:9 или 4:3); рамка, найденная раньше, сохраняется, если она по-прежнему точнее.
- **Вебка + игра** — маленькое лицо стоит на месте в углу кадра: вебка сверху (крупно, 820 из 1920 px — `render.cam_height`), экран снизу.
- **Кадр по лицу** — вебка на весь экран, «общение», IRL: вертикальный кадр следует за лицом. Камера двигается плавно и не дёргается от каждого движения. Если человек далеко, кадр немного приближается.
- **Только вебка** — вебка в углу, а основной экран пустой (чёрный или однотонный, без текста и деталей): вебка крупно на весь экран, кадр следует за лицом и не выходит за границы картинки камеры. Белая страница сайта с текстом пустой не считается.
- **Размытый фон** — лица нет: весь кадр по центру на размытом фоне.

Раскладку можно закрепить для стримера в его карточке, а при ошибке указать положение вебки вручную.

**Мат** ищется по корням с приставками, с белым списком похожих обычных слов (вебка, себя, хлеба…). По умолчанию начало слова (~0,1 с) звучит как есть, а остальное делается глухим, «как через стену». Понятно, что сказано, но слово не звучит, и не бывает провалов тишины, даже если мата много. В субтитрах слово маскируется: «Б***Ь». Другие режимы: `censor.mode: muffle` (глухое всё слово), `mute` (тишина), `beep` (тон). Свои слова добавляются в `data/profanity_extra.txt`.

**Качество.** Для Twitch плейлист запрашивается с поддержкой HEVC/AV1, поэтому берётся 1440p, если стример его транслирует (раньше максимум был 1080p). Качество исходника показано на карточке клипа. Финальный клип — 1080×1920, но с более чёткой картинкой за счёт уменьшения из 1440p.

**Концовка клипа.** Claude видит не только сам момент, но и 40 с до него и 90 с после, поэтому может продлить клип, пока история не досказана. Длинная тишина (пропал звук, упал стрим) помечается в расшифровке, и клип через обрыв не тянется. Моменты, которые опасно выкладывать (реальное насилие, аварии, оружие, наркотики, 18+), отбрасываются.

**Кеширование.** Каждый этап сохраняется в папку задачи. «Переанализировать» заново запускает только Claude (речь заново не распознаётся), «Перемонтировать» — только монтаж.

## Обучение на ваших оценках

У каждого клипа есть две кнопки:
- **«Не подходит»** — выберите причину (скучно, непонятно без контекста, плохо обрезано…). Такие моменты Claude будет избегать.
- **«Выложил»** — вставьте ссылку на ролик в TikTok (подходит и короткая `vm.tiktok.com/…`). Просмотры, лайки, комментарии и репосты подтянутся сами и будут обновляться: свежие ролики раз в 3 часа, старше недели — раз в сутки. Без ссылки цифры можно ввести вручную.

На странице «Статистика» видны просмотры, лайки, график роста каждого ролика, медианы по типам моментов и по длине клипа. При каждом анализе Claude получает примеры этого канала: что залетело (с долей лайков, комментариями и длиной), что зашло слабо, медианы по типам и длине, последние отклонённые с причинами и вашими комментариями. Чем больше отметок, тем точнее выбор. Данные хранятся в `data/feedback.json`.

## Длина, ускорение и паузы

**Длина** клипа больше не подгоняется под 30 или 60 секунд. Claude выбирает её по смыслу: шутка может длиться 10–20 секунд, история или новость — 1–3 минуты. Предел безопасности — `clips.max_duration` (180 с).

**Вода внутри клипа.** Claude отмечает куски, которые мешают смотреть: чтение доната не по теме, «чат, подождите», поиск чего-то без комментариев, повтор той же мысли. Они вырезаются целыми фразами; на карточке клипа видно «−N с воды».

**Паузы.** «Мёртвые» паузы в речи (стример задумался, тишина) вырезаются автоматически: остаётся по 0,15 с с каждой стороны, чтобы речь звучала естественно. Паузы со смехом, реакцией или звуком игры не трогаются: проверяется громкость звука. У историй и новостей сокращаются паузы длиннее 0,7 с, у смешного — только длиннее 1,2 с, чтобы не сломать паузу перед панчлайном. Субтитры, заглушение мата и зумы автоматически сдвигаются под новый монтаж.

**Ускорение и перемонтаж.** У каждого готового клипа можно выбрать 1×, 1.1×, 1.25×, 1.5× или 2×, включить или выключить вырезание пауз и сменить раскладку (вебка + игра, только вебка, кадр по лицу, весь кадр). Затем нажмите «Применить»: перемонтируется только этот клип, без повторного анализа.

## Плавность, синхронизация и концовка

- Клипы с 60-кадровых стримов монтируются в 60 к/с, остальные — в 30. Время кадров берётся по их настоящим меткам: у записей Twitch частота плавает (например 56–58 к/с), и раньше из-за этого звук уезжал от картинки, а видео «подтормаживало».
- Битрейт ограничен ~12 Мбит/с: для TikTok качество то же, а ролик плавно играет даже на слабом ноутбуке и по Wi-Fi.
- В конце клипа картинка и звук мягко затухают (`render.fade_out: false` — выключить). «Наезды» камеры на реакции убраны (`render.zoom: true` — вернуть).

## Качество 1440p

Twitch отдаёт «источник» (1440p) только при подключённом аккаунте и запросе с поддержкой HEVC/AV1. Подключите аккаунт на странице **«Статус → Twitch и качество видео»**: вставьте cookies twitch.tv или только `auth-token`. Там же можно проверить, какие качества доступны у конкретной записи. Используемое качество показано на карточке клипа.

## Прямой эфир

В карточке стримера включите **«Следить за эфиром»**. TwitchCut раз в 2 минуты проверяет, начался ли эфир. Когда эфир идёт, в «Задачах» появляется задача эфира (красная точка, «в эфире»), а в карточке стримера — ссылка «открыть клипы». **Клипы появляются прямо на этой странице во время эфира**, не дожидаясь конца: эфир разбирается кусками по часу, клипы за час появляются через 5–15 минут после его конца.

Как это работает: раз в час TwitchCut берёт новый кусок записи (Twitch пишет VOD параллельно с эфиром), начиная с самого начала эфира, даже если TwitchCut включили позже. Моменты ищутся так же, как для записи, и сильные сразу монтируются (оценка 60+, до 6 за кусок). Кусок, который не обработался из-за ошибки, автоматически повторяется (до 3 раз). Если сильных долго нет, раз в 20 минут эфира монтируется лучший из найденных (с оценкой от 50), помеченный «запасной». На странице эфира есть таблица по кускам: сколько моментов найдено, лучшая оценка, сколько смонтировано, были ли ошибки. После конца эфира дообрабатывается хвост. Клипы эфира хранятся отдельно (`workspace\live_<id>`), поэтому обычная нарезка той же записи их не затирает.

- **Звук куска** качается сегментами напрямую из плейлиста записи (параллельно, обычно меньше минуты на 15 минут эфира), а Claude перечитывает ещё 5 минут до куска, чтобы понимать контекст. История, которая упирается в конец куска, не режется, а целиком берётся в следующем куске.
- **Точное время слов.** Перед монтажом звук клипа ещё раз распознаётся на процессоре (faster-whisper), и время каждого слова субтитров берётся оттуда: основное распознавание на видеокарте ставит время слов внутри фразы приблизительно, из‑за чего субтитры то торопились, то догоняли. Текст субтитров при этом не меняется. Добавляет ~15–25 с на клип; выключается в `config.yaml` → `render: subtitle_retime: false`.
- **Распознавание в эфире** идёт кусками по 10 минут на видеокарте и процессоре одновременно — час эфира распознаётся примерно в 2–3 раза быстрее, чем одной видеокартой.
- **Синхронность субтитров.** Перед монтажом каждого клипа звук расшифровки сверяется со звуком видеофрагмента: небольшой сдвиг поправляется автоматически, а если звук не совпал вовсе — речь клипа распознаётся заново прямо по его видео. Ручная поправка: `render: subtitle_shift` в `config.yaml` (+0.2 — субтитры на 0.2 с раньше).
- **Если Claude не смог оценить кусок** (не авторизован, лимит), клипы эфира по одним только сигналам чата и громкости не монтируются: без смысла они обычно непонятны.
- **Быстрее, но мельче.** В `config.yaml` → `live:` можно поставить `min_chunk_minutes: 15` и `max_chunk_minutes: 15` — клипы будут появляться быстрее, но Claude будет видеть меньше контекста.
- **Нагрузка на ПК.** Между проверками почти нулевая. Раз в ~10 минут: скачать ~7 МБ звука, 1–3 минуты распознавать речь, 1–2 запроса к Claude, около минуты на монтаж каждого клипа. В среднем это примерно 20–35% процессора на протяжении эфира, памяти около 1.5–2 ГБ.
- **Ограничения.** У стримера должны быть включены записи трансляций (VOD). ПК и TwitchCut должны быть включены во время эфира. Обычные нарезки и эфир обрабатываются по очереди, чтобы не перегружать ПК.
- **Настройки** — раздел `live` в `twitchcut/config.py`: интервал, порог оценки, лимит клипов.

## Место на диске

Через 2 дня у задачи автоматически удаляются скачанное видео, звук и готовые ролики. Остаются названия, хештеги, оценки, расшифровка, превью, статистика и отметки «Выложил / Не подходит». Ролик можно смонтировать заново кнопкой «Применить» (видео скачается ещё раз, пока запись есть на Twitch). Срок меняется в `config.yaml` → `cleanup.keep_days`. На странице «Статус» видно, сколько места занято, и можно очистить вручную.

## Распознавание речи на видеокарте

`setup_gpu.bat` скачивает [whisper.cpp](https://github.com/ggml-org/whisper.cpp) в сборке с Vulkan (работает на AMD Radeon, Intel и NVIDIA, в том числе на встроенной графике) и модель `large-v3-turbo` (~550 МБ) в `tools\whispercpp`. После этого стрим распознают **одновременно видеокарта и процессор**: куски по 10 минут достаются тому, кто освободился первым. Обычно это в 2–4 раза быстрее, а модель на видеокарте ещё и точнее.

- На странице «Статус» видно, какая видеокарта используется и с какой скоростью она распознаёт.
- Если видеокарта даст сбой, работа продолжится на процессоре, ничего не потеряется.
- Сборка для Windows — сторонняя ([jerryshell/whisper.cpp-windows-vulkan-bin](https://github.com/jerryshell/whisper.cpp-windows-vulkan-bin)); `setup_gpu.bat` проверяет её контрольную сумму.
- Настройки в `config.yaml` → `whisper`: `backend: faster-whisper` вернёт распознавание только на процессоре, `hybrid: false` — только видеокарту. Другую модель (например `ggml-medium-q5_0.bin`, если видеокарта слабая) можно положить в `tools\whispercpp\models` и указать в `whisper.whispercpp_model`.

## Анализ через Claude

По умолчанию анализ идёт через **Claude Code по вашей подписке** (`claude -p`), моделью **Sonnet**: золотая середина между качеством и расходом лимитов. За токены отдельно не платите, расходуются общие лимиты подписки.

| Режим | Когда выбирать |
|---|---|
| Claude Sonnet | По умолчанию: хорошее понимание юмора и контекста |
| Claude Haiku | Быстрее, расходует меньше лимитов; для черновых прогонов |
| Claude Opus | Максимальное качество; расходует лимиты заметно быстрее |
| Вручную | Промпт копируется в чат claude.ai |
| Без Claude | Только сигналы чата и звука |

Глубокий анализ 3-часового стрима — это примерно 6–8 запросов на чтение стрима и 3–4 на оценку. Если лимиты подписки заканчиваются слишком быстро, поставьте `scan.model: haiku`: стрим будет читать Haiku, а финальную оценку по-прежнему делает Sonnet.

Если лимит подписки закончится, TwitchCut не упадёт: смонтирует клипы по сигналам чата и звука и покажет предупреждение. Позже можно нажать «Переанализировать».

## Если что-то не так

- **«Claude Code не авторизован».** Запустите `login_claude.bat`.
- **«Twitch не отдаёт чат».** TwitchCut сам пробует разные способы. Если не вышло, скачайте чат через [TwitchDownloaderCLI](https://github.com/lay295/TwitchDownloader) (`TwitchDownloaderCLI chatdownload --id 123456789 -o chat.json`) и укажите файл в «Новая нарезка → Дополнительно» (или `--chat chat.json`).
- **Вебка не найдена или найдена неправильно.** В карточке стримера нажмите «Указать» и обведите вебку мышкой, затем «Перемонтировать».
- **Журнал.** Всё, что происходит (в том числе в эфире), пишется в `data\logs\twitchcut.log` — пригодится, если что-то пошло не так.
- **Мало клипов.** Уменьшите `clips.min_score`.
- **Медленно распознаётся речь.** Запустите `setup_gpu.bat` (распознавание на видеокарте). Ещё можно выбрать «Быстрый» анализ.
- **Перезапуск.** Если закрыть TwitchCut посреди работы, после запуска `start.bat` задача продолжится сама: распознанные куски, прочитанные Claude части стрима, оценённые пакеты и смонтированные клипы сохраняются по мере готовности.
- **Видео монтируется с артефактами.** Поставьте `render.encoder: libx264` (кодирование на процессоре).
- **VOD только для подписчиков** пока не поддерживаются.
